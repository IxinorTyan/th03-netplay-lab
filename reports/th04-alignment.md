# TH03 对齐 TH04：2026-10-08

## 已确认的实现差异与修正

两者使用同一 NP21 WASM（SHA-256 `d64bbe39549a48686b1ed04fbadec68d8b33643d220395a9c09b8d54834f36e4`），不是换成了不同性能的模拟器。

| 路径 | 原 TH03 | TH04 / 当前 TH03 |
|---|---|---|
| WASM 间接调用 | 每次 `wasmTable.get()` | 审计过的静态函数表缓存，单机与联机同时启用 |
| 单机循环 | 原始 NP21 调度 | 60 Hz 上限适配器，原生 elapsed-time 模拟保持原样 |
| 单机显示 | 隐藏原生 canvas 再复制到可见 2D canvas | 原生直接绘制可见 canvas，保留 WebGL 路径 |
| 联机任务预算 | 一次最多 6 步，无耗时预算 | 每次最多 4 步，达到 6 ms 后让出主线程（单步本身不能中断） |
| 回滚补算 | 补算也消耗推进新帧的时间预算 | 补算与新帧预算分离，补算前尽早发送当前输入 |
| 回滚显示 | 跳过全部重播，等后续新帧刷新 | 最后一个补算帧允许显示，丢弃的中间帧不上传 |
| 定期校验 | JS 遍历全部 20.5 MiB WASM heap | 遍历 640 KiB DOS 游戏内存；`fullHash=1` 保留原完整校验用于测试 |
| 联机显示调度 | 独立 rAF 复制，可能复制旧画面 | 模拟结束后按 60 Hz 上限呈现，只复制新上传的画面 |
| 原声音效缓冲配置 | 100 ms | 与 TH04 联机相同的 40 ms |
| 回滚音效恢复 | 清空所有未确认音效 | 保留恢复点之前的音效，只丢弃恢复点之后的输出 |

回滚快照池本身与 TH04 基本相同：20.5 MiB 全状态快照、最多 13 个缓冲、文件写入撤销日志。本轮没有缩减必要的恢复状态。

开启真实回滚的双端测试另外发现：原客户端消息分发与 Relay 白名单遗漏 `rollback` 启用包。已补全接收，并更新原 HTTP/Relay 测试的设置字段和协议号，覆盖这类包的端到端转发。

## 独立音乐

- 从原始 PF 档案提取 21 首 TH03 PMD `.m` 曲目；日文和中文版本资源已逐字节比对一致。
- 复用 TH04 的 PMD 离线渲染器与 Opus 参数：64 kbps、constrained VBR、48 kHz、intro + 单次循环及原生循环点。
- `WEBMUSIC.COM` 改编自 TH04 的 PMD 桥接器。INT 60h 捕获真正的播放、停止、淡出、音量事件，哈希识别已加载的曲目。
- PMD 音乐声部 0..14 全部屏蔽，音效声部 15 保留。
- TH03 的配置仍保留 FM 命令路由（`YUME.CFG[0]=1`）。它的 `snd_active=0` 会关闭选曲指令；不能把这一个配置字节置零当成完整独立音乐实现。原生音乐实际输出由桥接器静音。
- 与 TH04 当前 MAIN 的 BGM OFF 补丁存在实现差异：这里保留 PMD 乐曲计时以保证原生等待小节/淡出逻辑正常；浏览器音乐不依赖该计时推进。
- 联机只在确认帧提交音乐事件。回滚恢复 reader 状态并丢弃预测事件，已开始的 Web Audio 音源不会因网络等待重新播放或按帧补 PCM。
- 音乐资源按需下载/解码，不阻塞游戏开局；设备音频时钟负责连续播放。

## 验证与诊断

`tools/test_music_page.cjs` 启动真实 DOS，检查选人曲、战斗曲、Opus 解码，并确认暂停模拟器后音乐时钟仍推进。

设置 `PROFILE` 输出文件路径可生成单机性能报告；`TABLE_CACHE=0` 仅在测试中通过脚本路由关闭函数表缓存。桌面浏览器 CPU 2 倍降速仅用于对照，不等于手机实测。结果见 `music-perf-cached.json` / `music-perf-uncached.json`。

更可靠的固定游戏帧对照见 `tools/profile_dispatch.cjs` / `dispatch-comparison.json`：相同 1380 个模拟步、218 个原生战斗计数、完全相同的 DOS 内存校验值，在 2 倍 CPU 降速下缓存前平均 41.14 ms，缓存后 24.96 ms，减少约 39%。单机 wall-clock 循环在降速后会发生时间追赶，测量波动很大，不能把某次“2 fps 对 60 fps”视作稳定提升倍率。

`music-perf-cached-native.json` 是不降速的桌面单机测试：59.96 模拟步/秒，56.30 次画面上传/秒，平均 6.67 ms/步。上传计数和模拟步数是不同指标；本次没有手机实测。

页面“性能与音乐状态”分别显示模拟步数、画面上传、显示提交、模拟/快照/校验耗时和补算步数。显示提交是 Canvas/WebGL 提交计数，不等于屏幕物理刷新率。

其他检查：原始磁盘及补丁审计、原生 TSR 指令测试、确认帧音乐队列/回滚测试、快照恢复测试、双浏览器全内存校验联机测试。手机稳定 60 帧仍需在具体手机上验证。

最终 WebRTC 与 Relay 均通过真实双浏览器测试（强制 `rollback=1&fullHash=1`），覆盖选人/对战、两端独立音乐、暂停时音乐不中断、触摸与蓄力、延迟传输、页面隐藏/恢复、降参；没有检测到全内存校验差异。触控页面、原生触控、快照、音乐、资源审计与 HTTP/Relay 测试均通过。

构建顺序：`python tools/build_pause.py`，资源需要重建时运行 `python tools/build_local_bgm_assets.py`，最后 `python tools/build_lockstep_runtime.py`。所有修改局限于 TH03，TH04 仅作为只读参考。
